# Results: the API (step 5)

Generated by `scripts/run_api_check.py`. The database behind it: [the vector database](results-database.md).

## Setup
- **The API:** FastAPI 0.143.0 on uvicorn 0.54.0 (one worker), on this computer (macOS arm64). PostgreSQL 18.6 with pgvector 0.8.7 in Docker, and nomic-embed-text through Ollama 0.35.0.
- **Endpoints:** `GET /search` (`q`, `method` = hybrid, vector, or keyword, `k` up to 50), `GET /controls/{id}`, and `GET /health`. The interactive docs are at `/docs`.
- **Search:** keyword (BM25, in memory) and exact vector search in the database, each a top 100, fused for hybrid with reciprocal rank fusion (k = 60) and the vector list weighted 3 times, as chosen in step 4.
- **The run:** a fresh API for each method, one warm-up question, then all 203 questions twice over HTTP: first when each question is new, then when it has been asked before (its embedding comes from the API's cache).

## Reading these numbers
- **embed:** turning the question into a vector with the local model; skipped when the question was asked before. **vector:** exact search in the database. **keyword:** BM25 in memory. **fuse:** reciprocal rank fusion.
- In the first round, the other parts are slower too: the database search took 9.32 ms, against 4.10 ms when the question was asked before. It runs right after the model, on the same computer; the cause wasn't investigated.
- Timings depend on the computer and include the trip from the client and back, so CI doesn't check them. CI does check the answers, with the committed embeddings standing in for the model.
