Generated by `scripts/run_mcp_check.py`. The answers it gives are measured in [cited answers](results-answers.md).

## Setup
- **The server:** `python -m controlfinder.mcp_server`, on the official MCP Python SDK (mcp 2.3.0), over stdio, started as its own process the way Claude Desktop or Claude Code start it, on this computer (macOS arm64).
- **Tools** (3, all read-only): `answer_question`, `get_control`, `search_controls`.
- **Search** runs in memory (step 5: same rankings as the database), so the server needs Ollama but no database.

## It returns the published rankings
- `search_controls` gave the published top 20 for 203 of 203 questions, with the model embedding each question live.

## Speed
- **Connecting** (starting the server and the MCP handshake): 336 ms. **Listing the tools:** 1 ms.
- **The first search:** 150 ms, which loads the catalog, the keyword index, and the embeddings. **Later searches:** 12.7 ms median, 15.8 ms at the 95th percentile.

## Reading these numbers
- **Expected** is what NIST links the question to, or the plain-English question's anchors. Citing more controls than that is the main weakness measured in [cited answers](results-answers.md).
- Times depend on the computer, so CI doesn't check them. CI does check the tools, their limits, and every question's search results through an MCP client, with the committed embeddings standing in for the model.
